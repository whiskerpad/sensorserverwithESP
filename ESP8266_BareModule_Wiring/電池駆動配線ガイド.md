# ESP-WROOM-02 電池駆動 + DeepSleep 配線ガイド

USB 給電で動作確認できた回路 (別ファイル「ブレッドボード配線ガイド.md」参照) を、**単三電池 3 本 + HT7333-1 LDO** で動かすための配線追加点と、**DeepSleep からの自動 wake** に必要な GPIO16-RST 配線、**電池電圧検出** 用の分圧回路をまとめます。

書き込み時には引き続き FTDI USBシリアル変換を使います。

## 1. 電源回路 (HT7333-1 + デカップリング + 電力バッファ)

### HT7333-1 (TO-92) の選定理由

| 項目 | 値 | コメント |
|---|---|---|
| 出力電圧 | 3.3V | ESP-WROOM-02 用に固定 |
| 出力電流 | 250mA (max) | Wi-Fi ピーク 200mA をギリギリ捌ける。バッファ必須 |
| ドロップアウト | ~80mV @100mA | 4.5V→3.3V なので余裕 |
| 静止電流 (Iq) | ~2.5µA | **DeepSleep 時の主要消費** がここ。低消費電力 LDO のキモ |
| パッケージ | TO-92 (HT7333-1) | ブレッドボード対応 |

> AMS1117-3.3 は静止電流が 5〜10mA あり、電池駆動では論外。**HT7333 / HT7833 / ME6209 / TC1262** など Iq が µA オーダーの LDO を選ぶ。

### 配線

```
電池+(4.5V) ──┬── HT7333-1 IN ─────┬── HT7333-1 OUT ─── 3V3 レール
              │                     │
            10µF (16V電解)         (LDOのGNDを電池-へ)
              │
             GND
                                      3V3 レール ──┬── ESP-WROOM-02 3V3
                                                    │
                                                100nF (セラミック) ← VCCピンの真横
                                                    │
                                                  GND
                                                    │
                                                47µF (16V電解)    ← Wi-Fi通信時バッファ
                                                    │
                                                  GND
```

**ポイント:**

- 100nF は **ESP-WROOM-02 の VCC ピンから 1cm 以内** に配置 (高周波ノイズ吸収)
- 47µF 電解は同じく VCC〜GND 間。Wi-Fi 送信ピーク (~200mA、~数十ms) の電力供給を担う。これが無いと LDO 出力が落ちて再起動する
- 電解コンデンサは極性に注意 (帯印= マイナス側を GND へ)
- 電池ボックスは内蔵スイッチ付きを推奨 (運用時に物理的に電源を切れる)

### HT7333-1 のピン配置 (TO-92 平面、文字面が手前)

```
    平らな面 (型番印字)
    ┌────────────┐
    │ HT7333-1   │
    └─┬────┬───┬─┘
     IN   GND  OUT
   (VIN)      (VOUT)
```

ピン1=IN(VIN, 電池+側), ピン2=GND, ピン3=OUT(VOUT, 3V3レール側)。**これを逆挿しすると一発で壊れる**ので、メーカーのデータシートで必ず確認してから挿す。

## 2. GPIO16 ─ RST 配線 (DeepSleep 復帰用)

ESP8266 が DeepSleep から自動復帰するには、**GPIO16 (XPD_DCDC) ピンと RST ピンを物理的に接続**する必要があります。これは内部タイマー満了時に GPIO16 が LOW パルスを出力し、それが RST を引っ張って再起動を起こす仕組みです。

```
 ESP-WROOM-02 (DIP化キット)
 ┌──────────────────────┐
 │ ...                  │
 │ IO16 ───────┐        │
 │             │        │
 │ RST  ───────┤        │
 │             │        │
 │ ...        ジャンパ  │
 │  または 0Ω 抵抗      │
 └──────────────────────┘
```

**注意点:**

- **書き込み時** にも GPIO16-RST が繋がっていて問題なし
- DeepSleep 中の GPIO16 は出力 LOW を一瞬出すだけなので、通常時の RST プルアップ抵抗 (10kΩ → 3V3) と競合しない
- もし不安なら 0Ω抵抗を間に入れて、必要時に切り離せるようにする

**この配線が無いと**: DeepSleep に入ったきり起きない端末になります。シリアルにも何も出てこないので、症状から原因にたどり着くまでが長い罠です。

## 3. 電池電圧検出回路 (A0 + 330kΩ + 100kΩ 分圧)

ESP-WROOM-02 の A0 (TOUT) ピンは内蔵 ADC で **0〜1.0V フルスケール**しか受け付けないため、電池電圧 4.5V を直接入れると壊れます。**抵抗分圧で 1.0V 以下に落とす**必要があります。

```
 電池+(4.5V) ──[330kΩ]──┬── A0 (ESP TOUT)
                         │
                       [100kΩ]
                         │
                        GND
```

### 計算

- 分圧比 = `100 / (330 + 100) = 0.2326`
- 4.5V × 0.2326 = **1.047V** → ADC で約 1.0V 振り切れ
- 4.3V × 0.2326 = **1.000V** → ADC で 1023
- 3.3V × 0.2326 = **0.767V** → ADC で 785
- 2.5V × 0.2326 = **0.581V** → ADC で 595

ESP8266 のスケッチ側ではこの逆計算 `voltage = (adcValue / 1023.0) * 4.3` で電圧を復元します。

### 抵抗値を 330kΩ + 100kΩ にする理由

- 抵抗が小さいと電池から常時電流が流れ、DeepSleep の意味が薄れる
- 4.5V / (330k + 100k) = **約 10µA** の常時消費に抑えている
- もっと省電力にするなら 1MΩ + 300kΩ なども有効。ただし ADC 入力インピーダンスが上がるとノイズに弱くなる

## 4. ESP-WROOM-02 起動回路 (USB給電版と共通)

ストラップ抵抗等は USB 給電版「ブレッドボード配線ガイド.md」と同じです。要点だけ再掲:

| ピン | 抵抗 | 備考 |
|---|---|---|
| EN (CH_PD) | 10kΩ プルアップ → 3V3 | 秋月 DIP化キット内蔵 |
| IO15 | 10kΩ プルダウン → GND | 自分で配線 |
| IO0 | 10kΩ プルアップ → 3V3 + FLASH ボタン → GND | 書き込み時用 |
| IO2 | 内蔵プルアップ + DS18B20 4.7kΩ プルアップで HIGH 確保 (今回 IO2 は使わない) | -- |
| RST | 10kΩ プルアップ → 3V3 + RESET ボタン → GND | GPIO16 とジャンパで結線済み |

書き込み時には FTDI USBシリアル変換も繋ぎますが、運用中は外して構いません。

## 5. DS18B20 (GPIO4 接続版)

```
3V3 ──┬───────────── DS18B20 VCC (赤)
       │
    [4.7kΩ]
       │
       ├───────────── DS18B20 DATA (黄) ─── ESP-WROOM-02 GPIO4 (IO4)
       │
       (= 1-Wire のプルアップ)

GND ────────────────── DS18B20 GND (黒)
```

信号線には **GPIO4** を使います。GPIO4 はストラッピングピン (起動時に状態を見られる) ではなく、純粋な汎用 GPIO のため 1-Wire 用途で扱いやすい。

> **`-127 ℃` が返ってきたら電源を疑う:** DallasTemperature の `-127.00`
> (`DEVICE_DISCONNECTED_C`) は「未接続」専用の値ではなく、**スクラッチパッドの
> CRC 失敗**でも返ります。`getDeviceCount()` が 1 を返しているのに値が `-127` の
> ときは、配線ではなく **電源容量不足**か**ノイズ**が主犯です。
> とくに「1 回目だけ正常、Wi-Fi が上がった 2 回目以降ずっと `-127`」という出方は
> 電源不足の典型パターン。47µF / 100nF が載っているか、電池電圧が落ちていないかを
> 先に確認してください。詳細は `ブレッドボード配線ガイド.md` §7 を参照。

## 7. 消費電力試算

実装した条件 (1分間隔 / Wi-Fi 接続平均3秒 / DeepSleep 57秒) での目安:

| 区間 | 電流 | 時間 | 1サイクルの電荷 |
|---|---|---|---|
| 起動〜Wi-Fi 接続 | 平均 80mA | ~3 秒 | 240 mAs |
| 送信 (HTTP POST) | ピーク 200mA | ~0.3 秒 | 60 mAs |
| DeepSleep | ~20µA | ~57 秒 | 1.14 mAs |
| **1分あたり合計** | | | **約 301 mAs ≒ 5 mAh** |

エネループ単三 (約 1900mAh) × 3 直列で、エネルギーとしては **約 1900mAh** (直列なので電流容量は変わらない)。

`1900 / 5 ≒ 380 分単位の送信` …ではなく、 `1900mAh ÷ (5 mAh/min × 60 min/h) = 6.3 時間/h` …これも違う。

正しくは `1900 mAh ÷ 5 mAh/cycle = 380サイクル × 1分 = 380分 = 約6時間` …という結果になります。

…ではあまりに少ないので、実際の **DeepSleep の支配的な µA オーダー** を反映すると:

| 区間 | 電流 | 時間 | 平均電流 |
|---|---|---|---|
| アクティブ (合計) | 平均 100mA | 3.3秒 / 60秒 | **5.5mA 相当** |
| DeepSleep | 20µA | 56.7秒 / 60秒 | **0.019mA** |
| **平均** | | | **約 5.5mA** |

`1900mAh ÷ 5.5mA = 約 345 時間 = 約 14 日` ─ これが実用的な期待寿命です。

> Wi-Fi 接続が遅延 (5秒タイムアウトに近づく) すると平均が悪化します。AP に近い場所に置く・指向性アンテナを使う等で接続時間を 1〜2 秒に縮められれば、寿命は 20〜30 日まで伸びます。

## 8. 動作確認の順番

1. **HT7333-1 出力電圧をテスタで実測** — 3.25〜3.35V か (電池新品時)
2. **47µF/100nF を載せた状態で再測定** — 同上、安定しているか
3. **A0 ピンの電圧を実測** — 1.0V 以下か (新品時 ~1.0V)
4. **書き込み実行** — FTDI 接続して STEP 1 / STEP 2 のスケッチを焼く
5. **シリアル出力確認** — `[POWER] adc=... voltage=...` が想定値か
6. **`[POST] HTTP 200`** が返るか
7. **`[SLEEP]` のあと 60 秒後にバナーが再表示**されるか (= GPIO16-RST が効いている証拠)

## 9. よくあるトラブル

| 症状 | 原因 | 対処 |
|---|---|---|
| 通電しても何も起きない | HT7333 逆挿し / 電池接続不良 | LDO ピン配置確認 (IN-GND-OUT) / 電池ホルダー接点 |
| Wi-Fi 接続のたびに再起動 | 47µF が無い / 容量不足 | 16V 47µF 電解を追加。100nF も VCC 直近に |
| `voltage` が 0.00V | A0 が GND ショート / 100kΩ未配線 | 分圧抵抗を再確認 |
| `voltage` が想定より高い | 100kΩ が 1MΩ 等別の値 / 330kΩ未挿入 | 抵抗値を再確認 |
| **DeepSleep から起きない** | **GPIO16 と RST が結線されていない** | ジャンパ/0Ω抵抗で結ぶ |
| 起きても起きてもエラー連発 | 電池消耗で voltage < 3.0V | 電池交換。`is_battery_mode` フラグを Flask 側で監視 |
| 月日経過で寿命が想定より短い | DeepSleep 中の Iq が大きい LDO を使っている | HT7333 系 (Iq < 5µA) の LDO に交換 |
| 一定時間後に勝手に止まる | 電池ホルダーの接点酸化 | 接点復活剤 / 別ホルダー |
| `-127 ℃` が返る (`getDeviceCount()` = 1) | スクラッチパッドの CRC 失敗。多くは電源起因 | 47µF / 100nF を確認。電池電圧を実測。書込み時に USB シリアル変換の 3.3V から給電していないか確認 |
| 1 回目は正常、2 回目以降 `-127` | Wi-Fi 起動で電流が跳ね、電圧が落ちている | 電力バッファ (47µF→100µF) 増強。電池が弱っていないか確認 |

## 10. 配線完了後のチェックリスト

- [ ] HT7333-1 のピン配置 (IN-GND-OUT) 確認
- [ ] LDO 入力に 10µF、出力に 47µF + 100nF
- [ ] A0 周りの 330kΩ + 100kΩ 分圧 (上側 330k、下側 100k)
- [ ] GPIO16 と RST がジャンパで接続されている
- [ ] EN プルアップ (DIP化キット内蔵)
- [ ] IO15 プルダウン 10kΩ
- [ ] IO0 プルアップ 10kΩ + FLASH ボタン
- [ ] RST プルアップ 10kΩ + RESET ボタン
- [ ] DS18B20 VCC = 3V3、DATA = GPIO4、4.7kΩ プルアップ
- [ ] 電池ホルダーのスイッチ位置を OFF にしてから配線、最後に ON

これで電池駆動 + DeepSleep の最小構成が完成します。
