# STEP 2: ESP-WROOM-02 + DS18B20 → DeepSleep + Wi-Fi で Raspberry Pi (Flask) へ HTTP POST

## はじめに

STEP 1 ではシリアルモニターに温度を表示するだけでした。このステップでは

1. **単三電池3本 (4.5V) + HT7333-1 LDO** で 3.3V を作って ESP-WROOM-02 を電池駆動する
2. **1分ごとに DeepSleep から起き上がって計測 → Raspberry Pi の Flask サーバー (AP) へ HTTP POST → 再び DeepSleep**

という低消費電力・自律型 IoT 端末を作ります。Raspberry Pi 側は **wlan1 (USB Wi-Fi ドングル) を AP 化** して `192.168.4.1` のゲートウェイになっています (構築手順は別ドキュメント「Raspberry Pi DHCP/APセットアップガイド.md」参照)。

> **使用モジュールについて:** 本シリーズでは秋月電子の `ESP-WROOM-02 DIP化キット` (AE-ESP-WROOM-02) を使用します。技適認証 (工事設計認証番号 `206-000519`) 済みで、日本国内で電波を出すのに必要な要件を満たしています。書き込みは **FTDI USBシリアル変換** (3.3V ロジック) で行います。配線詳細は別ファイル **「電池駆動配線ガイド.md」** にまとめています。

## 全体構成

```
 ┌──────────────────────┐                      ┌────────────────────────┐
 │ ESP-WROOM-02 (×N台)  │                      │  Raspberry Pi          │
 │ + DS18B20            │ ───── Wi-Fi STA ──── │  wlan1 (USB ドングル)  │
 │ 単三3本 + HT7333     │   192.168.4.x        │  = AP iot-sensors      │
 │                      │                      │     192.168.4.1        │
 │ 1分ごとに            │   HTTP POST          │     DHCP サーバ        │
 │ DeepSleep → 起動 →   │   /api/sensor        │     Flask (受信時に    │
 │ 計測 → POST → Sleep  │   Content-Type:JSON  │       タイムスタンプ   │
 │                      │                      │       付与)            │
 └──────────────────────┘                      │                        │
                                                │  wlan0 (オンボード)    │
                                                │  = インターネット側    │
                                                └────────────────────────┘
```

ESP8266 側ではタイムスタンプを生成しません (RTC 不要なので電池が長持ち)。**Raspberry Pi 側で受信時刻を付与**するのが一番シンプルで誤差も小さい設計です。

## ハードウェアの要点

詳細は別ファイルに譲り、ここではコードに直結する要素だけ:

- **GPIO4** に DS18B20 DATA (DS18B20 VCC は 3V3 直結、4.7kΩプルアップ)
- **GPIO16** を **RST** に物理配線 (これがないと DeepSleep から起きてこない)
- **A0 (TOUT)** を電池+ から **330kΩ + 100kΩ で分圧** して接続 (電池電圧検出)
- **HT7333-1 出力** に 16V 47µF 電解 (Wi-Fi 通信時の電力バッファ)

## コード解説

### 1. setup() のみで処理する構造

```cpp
void setup() {
  // ... 計測 → 送信 → DeepSleep
}
void loop() {
  // 使わない (DeepSleep から起きると setup() から再実行)
}
```

DeepSleep に入ると ESP8266 はほぼ完全に電源を切り、設定された時間後にハードウェアリセットで再起動します。**再起動はソフトウェア状態を引き継がない**ため、いわゆる「無限ループの中で sleep する」ような書き方はできず、**1サイクルすべてを setup() で完結させる**のがセオリーです。

### 2. 電池電圧の読み取り

```cpp
int adcValue = analogRead(POWER_SOURCE_PIN);   // A0
float voltage = (adcValue / 1023.0) * 4.3;
bool isBatteryMode = (voltage < 2.5);

float batteryPercent = ((voltage - 2.5) / 0.8) * 100.0;
if (batteryPercent < 0.0) batteryPercent = 0.0;
if (batteryPercent > 100.0) batteryPercent = 100.0;
```

ESP-WROOM-02 内蔵 ADC は 0〜1.0V フルスケールのため、外部分圧で 4.5V を 1.0V 以下に落としています。330kΩ + 100kΩ の分圧比は `100/(330+100) = 0.2326` で、**A0 が 1.0V 振り切れる時の元電圧は 1.0 / 0.2326 ≒ 4.3V**。コードの `* 4.3` はこの逆算です。

電池残量は **3.3V を 100% / 2.5V を 0%** にスケーリングしています。HT7333-1 が安定動作する境界 (3.3V) を上限、ドロップアウト境界 (2.5V) を下限にしているので、表示が動き始めたら「もう電池交換時期」のサインになります。

> 新品電池 (4.5V) では計算上 225% になりますが、`if` でクリップして 100% 表示。LDO の出力は安定したままなので、**バッテリーが減り始めるまで 100% に張り付く**指標と理解してください。

### 3. DS18B20 計測 (warm-up convert + 本変換)

```cpp
sensors.begin();
deviceCount = sensors.getDeviceCount();
sensors.setResolution(SENSOR_RESOLUTION_BITS);  // 12bit
sensors.requestTemperatures();   // ① warm-up (スクラッチパッド初期値=85℃を上書き)
// ... Wi-Fi 接続中 ...
sensors.requestTemperatures();   // ② 本番計測
```

DS18B20 は電源投入直後、スクラッチパッドに 85.00℃ がデフォルトで入っています。Convert T を 1 度も成功させていないと 85℃ がそのまま読まれるため、**warm-up convert を 1 回叩いて中身を上書き**してから本番計測に入ります。Wi-Fi 接続が並行して行われている間に DS18B20 の変換 (~750ms) が終わるので、無駄なく 1サイクルを回せます。

### 4. Wi-Fi 接続 (5秒タイムアウト)

```cpp
WiFi.mode(WIFI_STA);
WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
unsigned long start = millis();
while (WiFi.status() != WL_CONNECTED && millis() - start < WIFI_TIMEOUT_MS) {
  delay(100);
}
if (WiFi.status() != WL_CONNECTED) {
  goToSleep();   // 失敗時は今回の送信を諦めてすぐ寝る
  return;
}
```

電池駆動では「接続できないのに無限に待ってバッテリーを消耗する」のが最悪なので、**5秒で見切りをつけて寝る**設計にしています。次のサイクル (60秒後) で再挑戦すればよいだけ。

### 5. JSON ペイロード (タイムスタンプ無し)

```json
{
  "device_id": "esp8266-01",
  "voltage": 3.31,
  "battery_percent": 78.5,
  "is_battery_mode": false,
  "rssi_dbm": -65,
  "sensors": [
    { "index": 0, "address": "28FFA1B2C3D4E5F6", "temp_c": 24.50 }
  ]
}
```

ポイント:

- **時刻は送らない** ─ Flask 側で受信時に付与。NTP コードを削除できるのでブート〜送信完了までが速くなり、結果的に消費電力も下がる
- `voltage` / `battery_percent` / `is_battery_mode` を加えた ─ 後から「電池切れの直前まで送っていた値」をデバッグできる
- `rssi_dbm` ─ AP までの電波強度。設置場所の改善判断材料

### 6. HTTP POST + DeepSleep

```cpp
WiFiClient client;
HTTPClient http;
http.begin(client, SERVER_URL);
http.addHeader("Content-Type", "application/json");
http.setTimeout(HTTP_TIMEOUT_MS);  // 5秒
int code = http.POST(payload);
http.end();

ESP.deepSleep((uint64_t)DEEP_SLEEP_SEC * 1000000ULL);
```

`ESP.deepSleep(マイクロ秒)` で寝かせます。`uint64_t` キャストは 32bit 範囲を超えないようにする保険 (60秒なら問題ありませんが、後で延ばす可能性に備えて)。**`Serial.flush()` を寝る前に必ず**入れて、ログがバッファに残ったまま落ちないようにします。

### 7. GPIO16 ─ RST 配線が必須な理由

DeepSleep からの wake は、**GPIO16 (XPD_DCDC) が内部タイマーで LOW パルスを出して RST を引っ張る**仕組みで実現されています。基板上で **GPIO16 と RST を物理ジャンパで結ぶ**必要があり、これが無いと「寝たまま起きてこない端末」になります。**最初の動作確認時に一番ハマるポイント**なので注意。

## Raspberry Pi 側 — タイムスタンプ付与の最小実装例

Flask の本体実装は STEP 4 で行いますが、受信動作確認用の最小スクリプト:

```python
# /home/pi/recv_test.py
from flask import Flask, request, jsonify
from datetime import datetime, timezone, timedelta

app = Flask(__name__)
JST = timezone(timedelta(hours=9))

@app.route("/api/sensor", methods=["POST"])
def recv():
    data = request.get_json(silent=True) or {}
    # 受信時刻を JST で付与
    data["server_received_at"] = datetime.now(JST).isoformat()
    print("RECV:", data)
    return jsonify(status="ok"), 200

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

```bash
python3 recv_test.py
```

ESP8266 を起動すると、`192.168.4.x` の DHCP アドレスが割り当てられ、60 秒ごとにこのコンソールに `RECV: {... 'server_received_at': '2026-05-02T15:30:00+09:00'}` が表示されます。

### 自分の PC からの疎通テスト

```bash
curl -X POST http://192.168.4.1:5000/api/sensor \
     -H "Content-Type: application/json" \
     -d '{"device_id":"test","voltage":3.3,"battery_percent":100,"is_battery_mode":false,"rssi_dbm":-50,"sensors":[{"index":0,"temp_c":25.0}]}'
```

Raspberry Pi の AP に PC から接続した状態でこれを叩くと、`{"status":"ok"}` が返るはず。Flask 側に問題がないことを先に確認してから ESP8266 を投入すると、切り分けが楽です。

## 電池寿命の見積もり

| 区間 | 電流 | 時間 | 1サイクルの電荷 |
|---|---|---|---|
| 起動〜Wi-Fi 接続 | 平均 80mA | ~3 秒 | 240 mC |
| 送信 | ピーク 200mA | ~0.3 秒 | 60 mC |
| DeepSleep | ~20µA | ~57 秒 | 1.14 mC |
| **1分あたり合計** | | | **約 301 mC ≒ 5 mAh** |

エネループ単三 (1900mAh × 3直列、ただしエネルギーは1900mAh分) で計算すると `1900 / 5 ≒ 380 サイクル/h` …ではなく、`1900mAh / (5mAh/min × 60min)` = 約 6 時間ごとに 30mAh、つまり **実用 200〜400 時間 (= 8〜16日)** が机上計算。実機では Wi-Fi の接続安定性で結構変わります。

> 電池が切れる直前は LDO がドロップアウトして電圧が落ちるため、`battery_percent` が 100 → 50 → 10 へと急降下します。この曲線を Flask 側で記録しておくと「いつ電池交換に行くか」の予測ができて便利。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| DeepSleep から起きてこない | **GPIO16 と RST の配線忘れ** | 0Ω抵抗または直接ジャンパで結ぶ |
| `[WiFi] connection failed (timeout)` | Raspberry Pi の AP 起動前 / SSID/PASS 違い / 距離 | hostapd が動いているか `systemctl status hostapd` で確認 |
| `[POST] failed: connection refused` | Flask が動いていない | `python3 recv_test.py` を起動しているか |
| `[POST] failed: No route to host` | ESP の IP が AP セグメント外 | ラズパイ dnsmasq の DHCP 設定確認 |
| `voltage=0.00V` / 一定値張り付き | 分圧抵抗の配線・断線 | 330kΩ/100kΩ の極性 (上下) を再確認 |
| `voltage` が想定より低い (3.1V とか) | 接点抵抗での電圧降下、電池消耗 | ジャンパ短く・太く。電池新品確認 |
| 30秒で連続再起動 | Wi-Fi ピーク電流で電源ドロップ | LDO 出力に 47µF が入っているか / より大きいバッファに |
| 起動するたびに端末番号が変わる | DHCP がランダム割当 | dnsmasq でMAC固定 IP 割当に変更 |
