# STEP 1: ESP-WROOM-02 (技適対応) + DS18B20 で温度計測 ― シリアル出力編

## はじめに

このシリーズの 1 ステップ目では、**ESP-WROOM-02** (技適認証あり) と **DS18B20** 防水温度センサーを組み合わせ、測定した温度を **Arduino IDE のシリアルモニター** に表示するコードを作成します。ここで動作確認ができれば、次のステップ (Wi-Fi 送信 → Raspberry Pi Flask サーバー → PC ダッシュボード) へ進む土台が整います。

### なぜ ESP-WROOM-02 か (技適について)

日本では、Wi-Fi/Bluetooth など電波を出す機器は **電波法に基づく技術基準適合証明 (技適)** を取った機器でなければ業務・実験を含めて使うと違法 (電波法第4条) になります。

- **ESP-WROOM-02**: Espressif 純正の技適認証モジュール (`R 201-160606`)。**日本で正式に使える ESP8266**
- ESP-12E / ESP-12F 系の海外通販製モジュール: **多くは技適非対応** で日本国内使用は違法

本シリーズでは秋月電子通商の **`ESP-WROOM-02 DIP化キット` (AE-ESP-WROOM-02)** を使用します。技適済み・2.54mm DIP ピッチに変換済みでブレッドボードに直接刺さります。

## 配線 (DS18B20 部分のみ抜粋)

```
ESP-WROOM-02 (DIP化キット)        DS18B20
──────────────────────────        ───────
3V3   ────────────────────────────── VCC (赤)
GND   ────────────────────────────── GND (黒)
IO2   ────────────────────────────── DATA (黄)
         │
       4.7kΩ
         │
        3V3  ← プルアップ抵抗 (必ず入れる)
```

> **ポイント:** DS18B20 は 1-Wire プロトコルを使います。DATA と VCC の間に **4.7kΩプルアップ**を入れないと正しく通信できず、`-127℃` というエラー値が返ってきます。
> このプルアップは ESP-WROOM-02 の `IO2` (GPIO2) を起動時に HIGH にしておく役目も兼ねるので、結果的に一石二鳥になっています。

ESP-WROOM-02 単体は USB ケーブル一本では起動しません。EN/IO15/IO0/RST のストラップ抵抗、LDO、書き込み用 USB-Serial の配線が必要です。詳細は配線ガイドを参照してください。

## コード解説

### ライブラリのインクルード

```cpp
#include <OneWire.h>
#include <DallasTemperature.h>
```

`OneWire` が 1-Wire バスの低レベル通信を担当し、`DallasTemperature` がその上に温度センサー専用の便利な関数を提供します。

### ピン定義とオブジェクト生成

```cpp
#define ONE_WIRE_BUS 2     // = ESP-WROOM-02 の IO2 (GPIO2)
OneWire oneWire(ONE_WIRE_BUS);
DallasTemperature sensors(&oneWire);
```

ESP-WROOM-02 DIP化キットのシルクで「IO4」と書かれているピンが GPIO4 です。GPIO 番号を直接書いておけばボード設定が `Generic ESP8266 Module` でも問題なくコンパイルできます (`D4` のようなピン別名記号は使えない点に注意)。

`DallasTemperature` に `OneWire` オブジェクトのアドレスを渡すことでセンサーを制御できます。

### setup() でセンサー検出

```cpp
sensors.begin();
deviceCount = sensors.getDeviceCount();
```

起動時にバス上の DS18B20 を自動検出します。**複数のセンサーを同じ DATA ライン**（D4）につなぐだけで、すべて読み取れるのが 1-Wire の大きなメリットです。

### loop() での温度取得

```cpp
sensors.requestTemperatures();          // 全センサーに変換指示
float tempC = sensors.getTempCByIndex(i); // インデックスで取得
```

`requestTemperatures()` を呼ぶと、接続されているすべてのセンサーが一斉に A/D 変換を開始します（変換時間: 最大 750ms）。その後 `getTempCByIndex()` で各センサーの値を読み出します。

### エラー値のチェック

```cpp
if (tempC == DEVICE_DISCONNECTED_C) { ... }
```

`-127.0` はセンサーが応答しない場合の戻り値です。プルアップ抵抗の確認、配線の再チェックを行ってください。

### `85.00℃` というマジックナンバー

DS18B20 のスクラッチパッド (内部 RAM) は、**電源投入直後 `0x0550 (= 85.00℃)` というデフォルト値で初期化される**ことがデータシートに明記されています。`Convert T` コマンドを 1 回も成功させていない状態でスクラッチパッドを読み出すと、そのまま `85.00℃` が返ってきます。つまり:

- **`85.00℃` ピッタリ = 「センサーは存在するが温度変換が一度も成功していない」のサイン**
- 物理的に存在するセンサーは検出 (アドレス取得) できているのに、Convert T → 750ms 待機 → スクラッチパッド読み出しの過程のどこかで失敗している状態

頻発する原因は次の通りで、**ほぼ全てハードウェア起因**です:

| 原因 | 確認方法 |
|---|---|
| プルアップ抵抗 (4.7kΩ) が未配線 / 値違い / 向き違い | DATA-3V3 間で抵抗値を実測 |
| DS18B20 の VCC が浮いている (寄生電源モード扱い) | DS18B20 の VCC ピンと GND 間で 3.3V を実測 |
| 3V3 レール電圧低下 (LDO 容量不足) | 動作中に 3V3 を実測。3.20V 以下なら NG |
| DS18B20 のケーブルが長すぎる / ノイジー | 一度 20cm 以内のジャンパで直結して試す |
| 偽 DS18B20 (海外通販の安価品で時々あり) | 別ロット / 信頼できる販売元のものに交換 |

本コードでは保険として 2 つの対策を入れてあります:

1. **`setup()` で初回ダミー変換** ─ ループ初回前にスクラッチパッドを実測値で上書きしておく
2. **`tempC == 85.00f` 検出時の再変換** ─ 1 度だけリトライし、それでも 85℃ ならエラー扱い

```cpp
if (tempC == 85.00f) {
  Serial.printf("[WARN] センサー[%d] 85.00℃ 検出 ─ 変換失敗の疑い、再試行します\n", i);
  sensors.requestTemperatures();
  tempC = sensors.getTempCByIndex(i);
  if (tempC == 85.00f) {
    Serial.printf("[ERROR] ... 再試行後も 85℃ ...\n");
    continue;
  }
}
```

> **注意:** 本当に 85℃ の環境にあるセンサー (例: 高温槽試験) ではこの判定が誤検出になります。家庭の室温計測用途では `85.00` ピッタリが「実温度」である確率は極めて低いので、この実装で問題ありません。高温計測する場合はこの判定を外してください。

### 分解能の明示設定

```cpp
sensors.setResolution(SENSOR_RESOLUTION_BITS);  // 12bit
```

DS18B20 は 9〜12bit の分解能を選べます (12bit = 0.0625℃, 750ms / 9bit = 0.5℃, 94ms)。前回起動時の設定値が EEPROM に残るので、明示的に設定しておく方が個体差・履歴に依存せず安定します。電源容量が厳しい場合は **9bit に下げると変換時間が短くなり成功しやすくなる**ことがあります。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| `'D4' was not declared in this scope` (コンパイル時) | ピン別名記号 (`D4` 等) は ESP-WROOM-02 単体用の `Generic ESP8266 Module` ボード設定では未定義 | GPIO 番号 (`4`) を直接書く (本コードはこの方針) |
| センサー数が 0 | 配線ミス or プルアップ抵抗なし | 配線を再確認。4.7kΩ抵抗を入れる |
| **`85.00℃` ばかり返る (一定値)** | スクラッチパッド初期値 = Convert T が失敗。プルアップ不足 / VCC 浮き / 電源容量不足 | DATA-3V3 間に 4.7kΩ、DS18B20 VCC が確実に 3.3V に来ているか実測。LDO 容量も確認 |
| 起動直後数回だけ `85.00℃`、その後正常値 | 初回変換前にスクラッチパッドを読んでいる | 本コードの初回ダミー変換処理が入っていれば解消。古いコードなら更新 |
| `-127.00 ℃` が出る | センサー未応答 | DATA ラインのプルアップ確認 |
| 値が不安定 | 電源ノイズ | 3V3-GND 間に 100nF デカップリングコンデンサを追加 |
| 書き込みエラー | ドライバ未インストール | CP2102 または CH340 のドライバをインストール |
| `Failed to connect` / 書き込みできない | フラッシュモードに入っていない | FLASH 押→RESET 押離→FLASH 離 の順で書き込み開始 (配線ガイド参照) |
| Wi-Fi接続のたびにリブート (STEP 2 で発覚) | 電源容量不足 | LDO を 1A 以上に。100nF を 3V3 ピン直近に |
